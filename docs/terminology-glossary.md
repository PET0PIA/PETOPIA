# PETOPIA 용어집 (한글 표기 표준)

화면 문구·주석·백엔드 메시지에서 같은 대상을 부르는 말이 갈라져 있어서 정리한 문서다.
영문 식별자(`Fair`, `Reservation`, `Booth`, `Business`/`Vendor`)는 이미 일관돼 있어 손대지 않는다.
**바꾸는 건 한글 표기뿐이고, API 필드명·enum 값·URL은 계약이라 그대로 둔다.**

## 1. 표준어

| 표준어 | 흡수한 말 | 대응 코드 |
|---|---|---|
| **행사** | 박람회, 펫페어, 페어 | `Fair` |
| **예약** | 예매, 티켓 예매 | `Reservation` |
| **참가업체** | 참가기업, 참여기업, 참여업체, 참여 업체 | `Vendor` (role) |
| **행사 관리자** | 박람회 관리자, 박람회 주최자, 페어업체, 행사관리자(붙여쓰기) | `EVENT_ADMIN` |
| **관람객** | 방문객(사람을 가리킬 때) | 예약자·입장자 |
| **부스** | — | `Booth` |
| **사업자** | — | `Business` (사업자등록 정보. 참가업체와 별개 개념) |
| **주최측** | 주최자 | 행사를 여는 조직 주체를 뭉뚱그려 부를 때 |

### 참가업체 vs 사업자 — 헷갈리는 자리

같은 회사를 가리키지만 축이 다르다. **역할**이면 참가업체, **등록 정보(`Business` 행)**면 사업자다.

| 자리 | 표준 표기 |
|---|---|
| `businessId`를 보여주는 라벨 | 사업자 ID |
| 정산 단위(`fair_id` + `business_id`) | 행사·사업자 조합, 사업자별 정산 |
| `Business.name` 입력·표시 필드 | 업체명 (회사 이름을 묻는 필드라 그대로 둔다) |
| 역할·권한·신청 문맥 | 참가업체 |

### 사람·역할 호칭 정리

| 역할 | 표준 호칭 | 비고 |
|---|---|---|
| `USER` | 관람객 | 계정 문맥에서는 "회원"(회원가입·회원 탈퇴) |
| `VENDOR` | 참가업체 | 사업자 등록을 마치고 부스로 참가하는 쪽 |
| `EVENT_ADMIN` | 행사 관리자 | 행사를 개최·운영하는 쪽 |
| `SUPER_ADMIN` | 최고 관리자 | — |

## 2. 예외 — 바꾸지 않는 것

바꾸면 안 되는 이유가 분명한 것들이다. 나중에 일괄 치환을 돌릴 때 반드시 제외한다.

| 대상 | 이유 |
|---|---|
| `사전예약` / `현장예매` | `ReservationType` enum(`ADVANCE`/`ONSITE_DIRECT`)의 고정 라벨. 두 유형을 구분하는 게 목적이라 "예매"를 남긴다 |
| 행사 고유명사 (`"2026 서울 펫페어"` 등) | 실제 행사 이름. mock 데이터·입력 placeholder 예시 |
| `이벤트` | 다른 개념 — 공지 카테고리 `EVENT`, 부스의 "판매상품·이벤트" |
| chat의 `티켓` | 다른 개념 — SSE 연결용 1회성 인증 티켓 (`ChatStreamTicketStore`, `useChatStream`) |
| `사업자` | `Business` 엔티티(사업자등록번호·상호). 참가업체(역할)와 구분해서 쓴다 |
| `고객` | 상담(chat) 문맥 전용 호칭 |
| 이미 적용된 `V*.sql` | Flyway 체크섬이 깨져 기동 실패. DB에 들어간 문구는 **새 마이그레이션의 UPDATE**로만 고친다 |

## 3. 자주 틀리던 자리

| 자리 | 통일 전 | 통일 후 |
|---|---|---|
| `EVENT_ADMIN` 콘솔 eyebrow | 박람회 관리자 / 행사 관리자 혼재 | 행사 관리자 |
| 헤더 비즈니스 메뉴 | 박람회 개최 신청 | 행사 개최 신청 |
| 홈 리뷰 섹션 | 박람회 리뷰 | 행사 리뷰 |
| 예약 진입 CTA | 예매하기 / 티켓 예매 | 예약하기 / 티켓 예약 |
| `FairStatus.RESERVATION_OPEN` 배지 | 예매 진행 중 | 사전예약 중 (목록 탭과 같은 말) |
| 행사 상세 참가업체 섹션 | 참가기업 | 참가업체 |
| 공개 목록 모집 배지 | 참가기업 모집중 | 참가업체 모집중 |
| 부스 신청 진입점 | 참여 부스 신청 | 부스 참가 신청 |
| 행사별 부스 목록 | 참여 기업 / 참여 업체 | 참가업체 |
| 정산 엑셀/표 헤더 | 티켓예매 총금액 / 행사업체금액 | 예약금 총금액 / 주최측금액 |
| 정산 엑셀/표 헤더 | 참가비용 총금액 | 참가비 총금액 |
| `businessId` 라벨 | 업체ID / 업체 ID / 참가업체(사업자) ID | 사업자 ID |
| `RESERVATION_DEPOSIT` 결제 유형 | 예약 예약금 | 관람객 예약금 |

### 함정 하나

`BoothSlotHallRef`의 주석에 있던 "페어"는 행사(fair)가 아니라 **쌍(pair)** 이었다.
`boothSlotId` + `hallId` 두 값을 묶은 객체라는 뜻이다. 용어 치환 때 이런 동음이의어를
먼저 걸러야 한다 — 지금은 "쌍(pair)"으로 바꿔 뒀다.

## 4. 새 문구를 쓸 때

- 행사를 가리키는 말은 무조건 **행사**. "박람회"는 서비스 소개 문장에서도 쓰지 않는다.
- 예약 행위는 **예약**. 유형을 구분해야 할 때만 "사전예약 / 현장예매"를 쓴다.
- 부스로 참가하는 쪽은 **참가업체**, 그 회사의 등록 정보는 **사업자**.
- 예약하고 입장하는 사람은 **관람객**. "방문"은 행위에만 쓴다(부스 방문, 방문일).
