# 마이그레이션 디렉터리

스키마 변경은 전부 이 디렉터리의 SQL 파일로만 한다. DB에 직접 DDL을 치지 않는다.

Flyway는 `V*.sql` / `R*.sql` 만 읽는다. 이 README는 무시된다.
(빈 디렉터리는 Gradle이 클래스패스로 복사하지 않아, 디렉터리를 유지하는 역할도 겸한다.)

## 파일명 규칙

| 형식                                 | 의미                                          |
|------------------------------------|---------------------------------------------|
| `V1__init.sql`                     | 버전 마이그레이션. 버전 오름차순으로 한 번만 실행된다.          |
| `V2__add_reservation_table.sql`    | 다음 변경                                       |
| `R__view_reservation_summary.sql`  | Repeatable. 내용이 바뀔 때마다 다시 실행된다. (뷰/프로시저용)  |

언더스코어는 **두 개**다. `V1_init.sql` 은 인식되지 않는다.

## 규칙

- **이미 적용된 파일은 절대 수정하지 않는다.** 체크섬이 어긋나 다음 기동이 막힌다.
  잘못 만든 컬럼도 되돌리지 말고 다음 버전 파일에서 고친다.
- **파일 하나에 변경 하나.** MySQL은 DDL이 트랜잭션으로 묶이지 않아, 한 파일에 여러 DDL을
  넣고 중간에 실패하면 절반만 적용된 상태로 남아 수동 정리해야 한다.
- **롤백(Undo)은 유료 기능이라 쓸 수 없다.** 되돌림은 항상 새 버전 파일로 한다.

적용 이력은 `flyway_schema_history` 테이블에서 확인한다.
